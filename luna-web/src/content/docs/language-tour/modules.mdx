## Provider vs Namespace

Luna strictly separates **artifact providers** from **module namespaces**:
- `import` selects a **provider** (`import <alloc>;` or `import "math";`)
- `module` defines a **namespace** within a provider file
- `::` accesses symbols inside a namespace (`math::add(1, 2)`)
- `using <path> as <alias>;` creates a local namespace alias

### Exporting from a Provider

```luna
// In math.ln (provider = "math")
export fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

export fn multiply(a: i32, b: i32) -> i32 {
    return a * b;
}

const SECRET = 42;  // Private by default
```

## Importing Providers

```luna
import "math";

fn main() -> i32 {
    dec result = math::add(1, 2);
    std::io::println("Result: {}", result);
    return 0;
}
```

## Namespace Aliases with `using`

```luna
import "math";
import <alloc>;

// Create local namespace aliases
using math as m;
using std::collections as col;

fn main() -> i32 {
    dec result = m::add(1, 2) * m::multiply(3, 4);
    dec map = col::HashMap<str, i32>::new();
    return result;
}
```

## Visibility (`export`)

Items in Luna are **private by default**. Use `export` to make them publicly accessible to other providers:

```luna
export fn public_function() { }        // Exported
fn private_helper() { }                // Private to this file

export struct PublicStruct {
    export name: str,                  // Public field
    id: u64,                           // Private field
};

struct PrivateStruct { };              // Private struct
```

## Standard Library Providers

Standard library capabilities are divided into dedicated providers:

```luna
import <core>;        // Foundational types, primitives, core traits
import <alloc>;       // std::Vec, std::String, std::Box, collections
import <io>;          // File, terminal, stream I/O
import <net>;         // Socket, TCP/UDP networking
```
